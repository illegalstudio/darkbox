# Example manifests

## Complete SDK lifecycle

[lifecycle.rs](lifecycle.rs) demonstrates typed manifest creation, streamed resources,
coherent SQLite snapshots, application-profile validation, immutable opening,
transactional edits, protected values/attachments, renaming and atomic saving.
Its public profile is [sdk-notes.md](profiles/sdk-notes.md).

```sh
cargo run --example lifecycle -- public.project
cargo run --example lifecycle -- protected.project protected
```

Each command creates and updates its named file. It requires an absent output
initially. Encryption/signing keys and deterministic nonces are public test data.
See the [SDK embedding guide](../docs/sdk.md) for production integration policies.

These are manifest examples for **fictional profiles**, not projects generated by existing software. They describe prospective archives and do not include the actual databases or images. The common specification does not mandate their schemas, paths or extensions.

| Example | Application data version | SQLite `user_version` | Resource model | Optional metadata |
| --- | --- | --- | --- | --- |
| [Notebook](notebook.manifest.json) | `"3"` | `12` | Text and attachments in one database; a logical FTS5 table | No creator or extensions |
| [Canvas](canvas.manifest.json) | `"7"` | Main `4`, history `2` | Two databases and image files with an explicit resource mapping | Creator software `"2.5.0"` and an optional presentation extension |

The different numbers deliberately show that a common specification version, application data version, individual database versions and creator software version are independent.

The [profile guidance](../docs/profiles.md) explains how to document an application format. Each example includes a self-contained profile document: [Notebook](profiles/notebook.md) or [Canvas](profiles/canvas.md).

To build an archive, copy all contents of the [canonical Darkbox 1.1.0 bundle](../archive/1.1.0/) into the ZIP root, preserving relative paths and every file's bytes. Do not include an enclosing `archive/` or version directory. Then add `manifest.json`, copy the matching application profile document to `application.profilePath`, which is `docs/profile.md` in both examples, and provide the declared SQLite databases and resource folders. The manifests declare all canonical documentation directories as well as their application directories. Perform container and profile validation in addition to JSON Schema validation.

The Canvas presentation extension is metadata-only. Its accent color can be preserved after ordinary project edits, so it is safe to mark it optional. It does not imply a directory or database of its own.

## Protected example

`cargo run --example protected -- example.project` creates a complete protected archive using the [protected-notes profile](profiles/protected-notes.md). It writes public test-key files alongside it for CLI verification. These deterministic, publicly known keys and nonces are strictly for demonstration. The example refuses existing output paths and cleans up staging files. Use a fresh destination directory for each run.

```sh
cargo run --example protected -- example.project
cargo run -- verify example.project --trust-store example.trust.json --require-protection
cargo run -- verify example.project --trust-store example.trust.json --decryption-keys example.keys.json --require-protection
```

The first verification checks the trusted signature, complete ciphertext inventory, public resources and SQLite integrity. The second additionally authenticates the encrypted attachment and SQLite BLOBs. Neither checks application plaintext semantics. The [binary/AAD/signature vectors](../archive/1.1.0/docs/darkbox/protection/1.0.0.vectors.json) provide exact independent interoperability inputs.

## Streaming creation and new editions

The [streaming example](streaming.rs) uses `PackageWriter` with prepared SQLite/attachment files, a public profile document and a generated 16 MiB reader. The writer includes canonical files, computes the complete inventory, signs the final manifest, validates the candidate and publishes atomically. The [API guide](../docs/library.md#progressive-package-creation) covers resource limits, reader behavior, trusted signing, unknown extensions and destination preservation.

```sh
cargo run --example streaming -- example.project
cargo run --example streaming -- example.project replacement
```

The second command publishes a complete new edition at the same destination, removing `assets/private.bin` and adding the already encrypted `assets/new.bin`. Both editions follow the [streaming-notes profile](profiles/streaming-notes.md). The example uses publicly known test keys and deterministic ciphertext; real applications supply secure key management and coordinated nonce allocation.
